| 8 | 2026-09-23 | Interview extras comparison uses comma-joined string containment against agreement text (deterministic, no model) — confirmed in compare tests. |
| 9 | 2026-09-23 | Demo mode is default entry; `?demo=1` and `?lang=` validated against enums; sample fixtures flow through the same Zod + verify pipeline. |
| 10 | 2026-09-23 | Clause segmentation: numbered/Clause/letter/roman/ALL-CAPS starts; merged to >=200 chars; split >2000 at sentence boundaries; stable IDs `c001…`. |

| 12 | 2026-09-23 | One AI call per full report (analysis), on-demand Ask and Negotiation wording, with session budget (default 12) and memoised results. |

| 17 | 2026-09-23 | Git root is the parent folder; the app lives in `rentready/`. CI uses `defaults.run.working-directory: rentready`; Cloudflare Pages root directory is `rentready` (HUMAN_TASKS.md). |
| 18 | 2026-09-23 | `vite preview` reads `public/_headers` (minus HSTS/`upgrade-insecure-requests`, which need HTTPS) so Playwright runs under the production CSP; e2e fails on any CSP violation or page error. | 19 | 2026-09-23 | vitest-axe 0.1 augments the legacy `Vi` namespace that Vitest 2 ignores; component tests call `axe()` via `tests/axe.ts#expectNoAxeViolations` instead of a custom matcher (no `any` augmentation needed). Colour contrast is checked in Playwright, not jsdom. |
| 20 | 2026-09-23 | App icon is a single SVG (`public/icon.svg`, `sizes: any`) — no PNG binaries in the repo; the duplicate `public/manifest.webmanifest` was removed because vite-plugin-pwa generates it. |
| 21 | 2026-09-23 | Header carries only a compact "Forget key" button (shown once a key exists); the full key panel stays on Upload and Settings. The full panel in the header overflowed 320 px by 186 px. |
| 22 | 2026-09-23 | `buildMatchRows` excludes `city` (context only, per INTERVIEW_SPEC) and `not_sure`/`not_discussed` answers; the interview UI also stores those choices as a skip. "Skipped ≠ mismatch" holds in both layers. |
| 23 | 2026-09-23 | Deposits in months are read by `parseMonthsCount` before `parseMoney`, so "two months" is 2 months of rent, not ₹2. Capped at 24 months. |
| 24 | 2026-09-23 | Interview options that need a number use follow-up inputs whose composed value is a string `normalise.ts` already parses (`"6 months"`, `"10%"`, `"45 days"`), so UI and verdict code share one format. |
| 25 | 2026-09-23 | Selecting a radio never auto-advances (arrow keys change the selection); Enter/Next submits. Number keys 1–9 pick options. Backspace-to-go-back was not added: it collides with text editing; the Back button and Shift+Tab cover it. |
| 26 | 2026-09-23 | Question/option/chip text lives in `en.ts` under `q.*`, `opt.*`, `chip.*` keys; a unit test fails if any is missing. Core `questions.ts` keeps English as a fallback for Node (eval). |
| 27 | 2026-09-23 | Demo flag moved into reducer state (`SET_DEMO`) — each `useDemoMode()` previously held its own copy. Preferences persist to `localStorage` and the demo flag to `sessionStorage`, both read back through Zod field by field; nothing else is stored. "Clear everything" removes every `rentready:` key, then `RESET_ALL`. |
| 28 | 2026-09-23 | `t()` language is synced inside `AppProvider` during render (idempotent `setLang`), so no screen renders a frame in the old language. |
| 29 | 2026-09-23 | The whole codebase was formatted with the repo's Prettier config once (it had never been applied); later diffs stay small. |
| 30 | 2026-09-23 | Segmenter rewritten: `emit()` never cleared its buffer, so every clause ≥200 chars was emitted twice and all later ids shifted; ALL-CAPS headings were capped at 8 *characters* (spec says 8 words), so "DISPUTE RESOLUTION" merged into the clause above; `pageEnd` was borrowed from the next clause. Now: numbered/headed clauses stand alone, plain paragraphs merge to ≥200 chars, >2,000 split at sentences, pageEnd = page of the clause's last line, bare headings carry onto the next clause, and a bare number starts a clause only before a capital (so wrapped lines like "11 months…" don't). |
| 31 | 2026-09-23 | Demo fixture clause ids realigned to the corrected segmentation (+1 from c002), the visitors quote made verbatim, and the sample deposit clause no longer says "at the time of vacating" (the demo is meant to show *no* refund timeline). `sampleData.test.ts` now fails if any recorded quote stops verifying. |
| 32 | 2026-09-23 | One intake entry point (`core/parsing/intake.ts`): size check before reading, magic bytes that must agree with the extension (`%PDF`+.pdf, `PK`+.docx), page/char caps, typed `IntakeError` codes mapped to specific i18n messages. DOCX uses the shared segmenter; DOCX/paste report `pageCount: 0` ("Read N clauses." without pages). |
| 33 | 2026-09-23 | Parsing is confirmed before checking: Upload shows "Read N clauses across M pages." and a "Check my agreement" button instead of auto-running analysis. `fileType: 'sample'` marks the bundled agreement so recorded demo responses can be limited to it (Phase 4/5). |
| 34 | 2026-09-23 | E2E builds a real PDF in memory (`e2e/pdf.ts`) and attaches it via `DataTransfer`, so real pdf.js + worker run under the production CSP with no binary fixture and without adding `@types/node`. jsdom lacks `Blob.arrayBuffer`; a test-only polyfill lives in `tests/setup.ts`. |
| 35 | 2026-09-23 | Rules judge the *agreement*, not the interview: `core/rules/extract.ts` reads rent, deposit (months preferred), lock-in, term and who-gives-which notice from clause text; verified model findings are the fallback; the interview is used only for the TDS rent. Previously DEPOSIT-HIGH and LOCKIN-LONG used what the user *said*, so the sample's 6-month lock-in went unflagged. |
| 36 | 2026-09-23 | Rules know whether the checklist was AI-checked (`aiChecked`). Offline, checklist-based rules (refund deadline, entry notice, maintenance, sale, dispute) use conservative text tests instead of treating "unclear" as "missing", which had flagged every agreement. |
| 37 | 2026-09-23 | Rule fixes against LEGAL_RULES: EVICTION-SELF-HELP fires when an owner may re-enter/take possession and *no* legal process is named (was inverted); GUEST-RESTRICTION catches "shall not permit any visitors … after 10 p.m."; MAINTENANCE-UNCLEAR no longer fires when maintenance is assigned; POLICE-VERIFICATION no longer depends on the dispute protection; tokens replaced everywhere; every text-triggered hit cites its clause. |
| 38 | 2026-09-23 | Verified evidence is keyed by clause **and** quote (`evidenceKey`) — keyed by clause alone, a second finding citing the same clause inherited the first one's quote and status. A checklist item marked "present" with no verified quote is shown as unclear. |
| 39 | 2026-09-23 | Local mode (`AnalysisResult.mode = 'local'`) produces no match rows: "not covered" without an AI read would be an unchecked claim. The report says "Offline check — no AI used" and shows checklist items as "Not checked yet". |
| 40 | 2026-09-23 | Routing: bundled sample + demo → recorded responses; any document with a key → Gemini; otherwise → local report (not an error). Recorded responses are never applied to the user's own document. Budget counts only real Gemini calls. |
| 41 | 2026-09-23 | Ask tab hidden until Phase 6 — the previous stub answered every question with a fixed "not in your agreement" card, which was dishonest. |
